# 🎨 우리반 그림판

초등학교 교실용 **실시간 협동 그림판 + 작품 감상 웹앱**입니다.
교사가 QR코드 하나를 띄우면 학생 20~35명이 각자의 태블릿으로 로그인 없이 들어와 그림을 그리고 제출합니다. 교사 화면에는 모든 작품이 실시간으로 모여 하나의 협동화처럼 채워집니다. 교사가 **‘느낌 나누기 시작’**을 누르면 모든 학생 화면이 감상 게시판으로 바뀌고, 학생들이 남기는 댓글은 교사 화면 오른쪽 중계창에 실시간으로 올라옵니다.

- 기술: Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Supabase (PostgreSQL · Realtime · Storage · Auth) · Vercel
- 설계 문서: [`docs/DESIGN.md`](docs/DESIGN.md) (화면, DB 구조, 권한 체계, 실시간 데이터 흐름)

## 1. 구현된 기능

| 영역 | 기능 |
|---|---|
| 접속 | QR코드 / URL / 6글자 코드 입장, 로그인 화면 없이 자동 익명 세션, 출석번호(버튼 선택) + 별명만 입력, 번호 중복 방지 |
| 그림판 | 4:3 흰 도화지, 14색 펜, 굵기 5단계, 지우개, 실행 취소·다시 실행, 전체 지우기(확인창, 되돌리기 가능), 크게 그리기(전체 화면), 자동 임시 저장(IndexedDB), 가로·세로 모드, 고해상도(DPR) 대응, 스타일러스 손바닥 거치 방지 |
| 제출 | 원본 1600×1200 + 썸네일 480×360 자동 생성·업로드, ‘제출 완료 / 고친 내용 있음’ 상태 표시, **재제출 시 학생당 작품 1개 유지 + 이미지 교체**(새 파일 경로라 캐시 문제 없음), 제출 이력 내부 보관, 네트워크 오류 자동 재시도 |
| 교사 갤러리 | 출석번호 순 격자, 화면 크기에 맞춰 열 수 자동 계산, 미참여/미제출(그리는 중) 표시, 접속 상태 점, 재제출 시 해당 칸만 부드럽게 갱신(‘수정 n회’), 작품 크게 보기(이전/다음), 협동화 보기(모자이크), 전자칠판 전체 화면 |
| 공개/숨김 | 작품별 숨김·공개, 전체 공개, 전체 숨김, 제출 작품만 보기 / 모든 학생 보기. 숨긴 작품은 학생 게시판과 이미지 파일 접근 모두 차단, 교사 화면에는 ‘숨김’ 표시 |
| 수업 단계 | 그림 그리기 → 느낌 나누기 → 활동 마무리 (다시 되돌리기 가능). 버튼 하나로 모든 학생 화면 자동 전환 + 전환 애니메이션, 늦게 들어온 학생도 현재 단계로 시작, ‘감상 중 그림 수정 허용’ 설정 |
| 감상 게시판 | 카드형 갤러리, 댓글 수, 작품 상세(큰 그림 + 댓글 + 입력창), 이전/다음 작품 이동, 안내 문구 순환, ‘인상 깊은 점 / 느낌 / 칭찬 / 색깔’ 말머리 버튼, 100자 제한, 3초 연속 등록 방지, 자기 작품 댓글 제한 |
| 댓글 중계 | 교사 화면 오른쪽 28%: [작성자 → 대상 작품] 내용·시각, 최신이 위, 새 댓글 강조, 누르면 해당 작품 확대, 숨기기/삭제, 댓글 쓰기 일시 중단, 중계 모드(댓글창 전체 화면 · 큰 글씨) |
| 관리 | 수업방 생성(학생 수 설정), QR 크게 보기·이미지 저장(제목·코드 포함), 주소 복사, 접속/참여/제출 인원, 미제출 목록, 학생이 기기를 바꿀 때 ‘번호 재설정’, 수업 종료, 수업방 삭제 |
| 결과물 | 전체 그림 ZIP(+댓글 CSV), 협동화 한 장 이미지(번호·별명 표시 선택), 댓글 CSV(엑셀 한글 호환), 개별 그림 다운로드, 지난 수업 다시 열람 |
| 안정성 | 연결 끊김 안내 배너, 재연결·화면 복귀 시 최신 데이터 자동 복구, 새로고침해도 같은 기기 세션·그림 복구 |
| 보안 | 모든 테이블 RLS, 클라이언트는 SELECT 만 가능하고 쓰기는 전부 권한 검사 RPC 경유, 비공개 Storage 버킷 + 서명 URL, service_role 키 미사용 |

## 3. 배포하기 (처음 하시는 분용, 순서대로)

### 3-1. 필요한 계정 (모두 무료로 시작 가능)
1. **GitHub** — https://github.com (코드 보관)
2. **Supabase** — https://supabase.com (데이터베이스, 실시간, 이미지 저장) → GitHub 계정으로 가입하면 편합니다
3. **Vercel** — https://vercel.com (웹사이트 배포) → GitHub 계정으로 가입

### 3-2. Supabase 프로젝트 만들기
1. Supabase 대시보드 → **New project**
2. 이름(예: `gurimpan`), 데이터베이스 비밀번호(아무 곳에나 적어 두기), Region 은 **Northeast Asia (Seoul)** 선택 → Create
3. 1~2분 기다리면 프로젝트가 준비됩니다.

### 3-3. 데이터베이스 설정 (SQL 한 번 실행)
1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 프로젝트의 `supabase/schema.sql` 파일 내용을 **전부 복사해서 붙여넣고 Run**
3. `Success. No rows returned` 가 나오면 완료. (테이블 6개, 보안 정책, 비공개 `artworks` 저장소, 실시간 설정이 한 번에 만들어집니다. 여러 번 실행해도 안전합니다.)

> 확인: 왼쪽 **Table Editor** 에 `rooms, participants, artworks, comments …` 가 보이고, **Storage** 에 `artworks` 버킷(Private)이 보이면 정상입니다.

### 3-4. 로그인 설정 ⚠️ 중요
왼쪽 메뉴 **Authentication** 에서:

1. **Sign In / Providers** → **Allow anonymous sign-ins** 를 **켭니다** (학생 자동 접속용).
2. **Rate Limits** → **Rate limit for anonymous users** 를 **30 → 300 이상**으로 올립니다.
   - 기본값은 *IP 하나당 시간당 30회*입니다. 학교에서는 반 전체 태블릿이 같은 공유기(같은 공인 IP)를 쓰므로 기본값이면 **31번째 학생부터 접속이 막힙니다.** 여러 반이 연달아 수업한다면 더 넉넉하게 잡으세요.
   - 한 번 접속한 태블릿은 세션이 저장되므로 새로고침해도 다시 세지 않습니다.
3. (선택) **Sign In / Providers → Email → Confirm email**
   - 켜 두면 교사 가입 시 인증 메일이 갑니다. Supabase 기본 메일은 시간당 발송 수가 매우 적으므로, 교사 몇 분만 쓰신다면 **끄는 것**이 편합니다. 끄면 가입 즉시 로그인됩니다.

### 3-5. API 키 복사
**Project Settings → API Keys** (또는 상단 **Connect** 버튼)에서 두 값을 복사합니다.
- **Project URL** — `https://xxxx.supabase.co`
- **anon public 키** 또는 **Publishable key**(`sb_publishable_…`) — 둘 중 하나

> ⚠️ `service_role` / `secret` 키는 **절대** 사용하지 마세요. 이 앱은 필요하지 않습니다.

### 3-6. 코드를 GitHub 에 올리기
1. GitHub → 오른쪽 위 **+ → New repository** → 이름 `gurimpan` → **Private** 권장 → Create
2. 방법 A (가장 쉬움): 저장소 화면의 **uploading an existing file** 링크 → 압축을 푼 프로젝트 폴더 안의 파일·폴더를 전부 끌어다 놓고 **Commit changes**
   (`node_modules`, `.next`, `.env.local` 폴더/파일은 올리지 마세요.)
3. 방법 B (git 사용):
   ```bash
   cd gurimpan
   git init && git add . && git commit -m "first"
   git branch -M main
   git remote add origin https://github.com/내아이디/gurimpan.git
   git push -u origin main
   ```

### 3-7. Vercel 배포
1. Vercel → **Add New… → Project** → GitHub 의 `gurimpan` 저장소 **Import**
2. Framework 는 자동으로 **Next.js** 로 잡힙니다.
3. **Environment Variables** 에 두 개 입력:

   | Name | Value |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | 3-5 의 Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 3-5 의 anon 또는 publishable 키 |

4. **Deploy** → 1~2분 뒤 `https://gurimpan-xxxx.vercel.app` 같은 주소가 생깁니다.
5. Supabase 로 돌아가 **Authentication → URL Configuration**:
   - **Site URL** = Vercel 주소 (예: `https://gurimpan-xxxx.vercel.app`)
   - **Redirect URLs** 에 `https://gurimpan-xxxx.vercel.app/auth/callback` 추가
   (이메일 인증을 켠 경우 인증 링크가 이 주소로 돌아옵니다.)

### 3-8. 첫 수업 준비
1. Vercel 주소 접속 → **교사 가입** → 로그인
2. 수업 제목, 학생 수 입력 → **수업방 만들기** → QR코드가 크게 뜹니다.
   - QR코드는 **현재 접속한 주소**로 자동 생성되므로 별도 작업이 필요 없습니다. 인쇄하려면 **QR 이미지 저장**.
3. 태블릿 카메라로 QR을 찍어 들어가 봅니다.

### 3-9. 태블릿 여러 대로 실제 접속 테스트 (수업 전에 꼭 한 번)
- [ ] 교사 PC 1대 + 태블릿 3대 이상을 **학교 Wi-Fi**에서 접속
- [ ] 태블릿마다 다른 번호로 입장 → 교사 화면에 ‘그리는 중’과 접속 인원이 늘어나는지
- [ ] 손가락과 터치펜으로 그려 보기 (화면이 스크롤되거나 확대되지 않아야 함)
- [ ] 제출 → 교사 화면에 1~2초 안에 나타나는지 / 고쳐서 다시 제출 → 같은 칸 그림만 바뀌는지
- [ ] 태블릿 한 대 새로고침 → 같은 번호와 그림이 그대로인지
- [ ] 태블릿 한 대 Wi-Fi 끄기 → 상단 ‘연결이 끊겼어요’ → 다시 켜면 자동 복구
- [ ] 교사 ‘느낌 나누기 시작’ → 모든 태블릿이 자동으로 감상 게시판으로 바뀌는지
- [ ] 댓글 작성 → 다른 태블릿과 교사 중계창에 바로 뜨는지
- [ ] 작품 숨김 → 학생 게시판에서 사라지는지
- [ ] 전자칠판에서 교사 화면 ⤢(전체 화면) 버튼

> 학교 방화벽이 `*.supabase.co` 웹소켓(wss)을 막으면 실시간 기능이 동작하지 않습니다. 상단에 ‘연결하는 중…’이 계속 보이면 정보 담당 선생님께 `*.supabase.co`, `*.vercel.app` 허용을 요청하세요.

### 3-10. 이후 기능 수정·업데이트 방법
- 코드를 고쳐 GitHub 에 올리면(커밋/푸시 또는 웹에서 파일 수정) **Vercel 이 자동으로 다시 배포**합니다.
- DB 구조를 바꿨다면 바뀐 `schema.sql` 을 SQL Editor 에서 다시 실행하세요(기존 데이터는 유지).
- 내 컴퓨터에서 미리 보려면:
  ```bash
  npm install
  cp .env.example .env.local   # 두 값 입력
  npm run dev                  # http://localhost:3000
  ```
  같은 Wi-Fi 의 태블릿에서 보려면 `npm run dev -- -H 0.0.0.0` 후 `http://내PC IP:3000` 으로 접속합니다.

## 4. 수업에서 쓰는 법

1. **준비**: 교사 화면에서 수업방을 만들고 QR코드를 전자칠판에 띄웁니다.
2. **그림 그리기**: 학생은 QR → 번호 선택 → 별명 → 그리기 → **그림 제출**. 고친 뒤 **다시 제출**하면 같은 칸이 새 그림으로 바뀝니다. 교사 화면 상단에서 제출 인원, ‘관리’에서 미제출 학생 목록을 봅니다.
3. **느낌 나누기**: 상단 **② 느낌 나누기 시작**. 필요하면 부적절한 작품을 👁 버튼으로 숨기고, 오른쪽 중계창에서 댓글을 숨기거나 삭제합니다. 너무 소란하면 **댓글 허용** 스위치를 끕니다. 중계창 ((•)) 버튼은 댓글만 크게 보여 줍니다.
4. **마무리**: **③ 활동 마무리** → 학생은 더 이상 그림·댓글을 바꿀 수 없습니다. **결과 저장**에서 ZIP·협동화·CSV 를 받습니다. 지난 수업은 대시보드에서 언제든 다시 열 수 있습니다.

**학생이 태블릿을 바꿔야 할 때**: ‘관리 → 참여 학생 → 번호 재설정’ 후 새 태블릿에서 같은 번호로 들어오면 기존 그림이 이어집니다.

## 5. 테스트

### 5-1. 실제로 실행해 통과한 자동 테스트
아래 세 가지는 이 저장소에 포함되어 있고, 개발 환경에서 실행해 모두 통과했습니다.

**① DB 권한·로직 테스트** — `npm run test:db` → **51개 통과**
실제 `schema.sql` 을 PostgreSQL(PGlite)에 적용하고 학생·교사 JWT 를 바꿔 가며 RLS·RPC 를 직접 호출합니다.
학생 30명 참여·제출, 같은 학생 3회 제출 → 작품 1개(version 3)·이력 3건, 번호 중복·범위 초과 차단, 다른 학생 파일 경로로 덮어쓰기 차단, 다른 수업방 ID 로 제출 차단, 숨긴 작품·숨긴 댓글·이전 버전 파일 비노출, 학생/다른 교사의 교사 기능 호출 차단, 테이블 직접 INSERT/UPDATE 차단, 단계별 제출·댓글 허용 여부, 3초 연속 댓글·빈 댓글·100자 초과 차단, 수업 종료 후 변경 차단, 수업방 간 데이터 0건 노출 등.

## 6. 운영 팁과 알아 둘 점

- **무료 요금제 제한**: 무료 Supabase 프로젝트는 일정 기간(약 1주) 사용이 없으면 일시 정지됩니다. 수업 전날 한 번 접속해 두거나, 정지되면 대시보드에서 **Restore** 하세요. 무료 저장공간(1GB)은 수업 한 번(30명 × 재제출 3회)에 약 30MB 정도 쓰므로, 오래된 수업방은 대시보드에서 결과를 내려받은 뒤 삭제하세요.
- **학생 세션**은 태블릿 브라우저에 저장됩니다. 시크릿(비공개) 모드나 ‘방문 기록 지우기’를 하면 새 학생으로 인식되니, 교사의 ‘번호 재설정’을 이용하세요.
- **교사 가입**은 주소를 아는 누구나 할 수 있지만, 각 교사는 **자기 수업방만** 보고 관리할 수 있습니다. 가입을 막고 싶다면 교사 계정을 만든 뒤 Supabase **Authentication → Sign In / Providers** 에서 신규 가입 관련 설정을 바꿀 수 있습니다. 다만 설정에 따라 **학생 익명 접속까지 막힐 수 있으니**, 바꾼 뒤에는 반드시 새 태블릿(또는 시크릿 창)으로 학생 접속을 확인하세요.
- 쌓인 익명 사용자(학생 세션)는 `auth.users` 에 남습니다. 많이 쌓이면 SQL Editor 에서 오래된 것만 지울 수 있습니다:
  `delete from auth.users where is_anonymous and created_at < now() - interval '90 days';` (해당 학생의 참여 기록은 남고 기기 연결만 해제됩니다)
